INTERVENTION SELECTION

Target
Not yet established. Contact Pattern Analysis documents a pattern of
frequent repeat calls and offers several possible functions, one of which is
reassurance-seeking / possible OCD-related mechanism — explicitly flagged
as "not established." A target such as "reduce reinforcement of a
reassurance-seeking pattern" cannot be stated as the intervention target
until that function is actually established, because behaviour (frequent
repeat calls) is not the same as function, and an unconfirmed hypothesis is
not a basis for defining what needs to change.

Established basis
What is established: a documented pattern of frequent repeat calls,
consistent with several possible functions. What is not established: which
function is operating. The reassurance-seeking / OCD-related mechanism is
explicitly named upstream as a hypothesis, not a finding. This skill
preserves that distinction rather than treating the hypothesis as the stated
basis for a response.

Selected response
Destination 6 — seek additional information before selecting an
intervention. The material does not yet support a specific target or
mechanism, so no intervention is proposed at this time. The proposed
ERP-informed protocol is not selected.

Mechanism
Cannot be completed. An ERP-informed protocol is designed to reduce
reassurance-seeking by preventing the reassurance response and allowing
anxiety to extinguish (exposure and response prevention logic) — but that
causal chain only holds if reassurance-seeking is in fact the operating
function. Since Contact Pattern Analysis has explicitly declined to
establish that, the sentence "we are doing X because we expect it to
influence Y through Z" cannot be completed concretely: Y (the function
being acted on) is not known to be true, only hypothesised.

Proportionality
Not assessable while the target is unestablished. Proportionality can only
be judged against a confirmed need; there is no basis here to say ERP-
informed restructuring is matched to, more than, or less than what's
required, because what's required hasn't been established.

Risks / unintended effects
Naming these for completeness, since the proposal is on the table even
though it isn't being adopted here:
- If the actual function is not reassurance-seeking (e.g. it relates to risk
  monitoring, loneliness, or another driver CPA left open), restructuring
  contact around response-prevention logic could withhold contact from
  someone whose pattern serves a different, possibly protective, purpose —
  increasing risk rather than reducing dependency.
- Selecting a named treatment modality on the strength of an unconfirmed
  hypothesis risks locking the case into a specific clinical frame before
  the frame itself is verified, which can be difficult to reverse once
  "ERP-informed" language enters the record and shapes how staff read
  future contacts.
- Treating an explicitly-flagged hypothesis as if it were established
  practice risks the reasoning shortcut this skill is built to avoid:
  upgrading a plausible function into a stated mechanism because a
  destination needs to be named.

Ownership
The missing piece is a current-risk-state finding and/or a contact-pattern
function determination — that belongs upstream (the skill(s) that produce
PORF and Contact Pattern Analysis findings), not to this skill. Route back
to the Clinical Workflow Router to determine what upstream work is needed
next; this skill does not dispatch which specific skill runs.

Review
Not applicable yet — no intervention has been selected, so there is no
review criterion to set. Once CPA (or equivalent) establishes the actual
function of the contact pattern, this skill should be re-run with that
established finding as input, and the six decision domains completed
against it.

Residual uncertainty
Whether reassurance-seeking / an OCD-related mechanism is in fact operating
remains unknown. Whether any other candidate function identified by CPA is
operating remains unknown. Whether the current contact pattern is causing
harm, is neutral, or is serving a protective function also remains
unestablished. All of this stays open pending upstream clarification — it
is not resolved, and is not being treated as resolved, by naming destination
6 here.
