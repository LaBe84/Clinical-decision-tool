# Clinical Model Source Register

This register separates named clinical models from local implementation choices.

| Model / framework | Current repository use | Source status | Required action |
|---|---|---|---|
| CASE suicide enquiry chronology | `skills/suicide-enquiry` | SOURCE NOT YET CONTROLLED | Add authoritative source/version; verify time-horizon labels and mandatory vs optional content |
| Prevention-Oriented Risk Formulation (PORF) | `skills/porf-formulation` | SOURCE NOT YET CONTROLLED | Add authoritative source/version; verify Risk Status, Risk State, Resources and Foreseeable Change definitions |
| Safety Planning | `skills/safety-planning` | SOURCE NOT YET CONTROLLED | Identify adopted model/source and distinguish model-required components from local usability enhancements |
| CARE | Operational/documentation framework discussed outside current promoted skill family | LOCAL SERVICE MODEL / SOURCE NOT YET CONTROLLED | Add canonical CARE specification and version when ready; keep distinct from reasoning skills |
| CRG decision logic | `skills/crg-triage` | LOCAL SERVICE DESIGN / APPROVAL SOURCE NOT YET CONTROLLED | Add current approved CRG guide/remit and governance status |
| CMP / Access Review | `skills/cmp-access-review` | LOCAL SERVICE DESIGN / APPROVAL SOURCE NOT YET CONTROLLED | Add current contact-management guidance, approval status and any mandatory thresholds |
| Contact Pattern Analysis | `skills/contact-pattern-analysis` | LOCAL CLINICAL DESIGN | Treat as local reasoning capability; validate operational data categories and governance status |

## Rule

A named model is not considered source-controlled merely because the repository contains a skill named after it. The skill is an implementation. The source register must identify the authoritative model/version separately.
